<interfaces>
Verified in a scratch project on 2026-10-16 with Prisma 7.10.1 (do not guess, follow this):
- Import the client from the generated output, NOT from `@prisma/client`: from `src/prisma/prisma.service.ts` the path is `../generated/prisma/client`; it exports `PrismaClient` (class and type), `Prisma`, enums such as `Role`, and model types `User`, `Url`, `Visit`.
- The Prisma 7 client cannot be constructed without a driver adapter: `new PrismaClient({ adapter })` where `adapter = new PrismaPg({ connectionString })` and `PrismaPg` is imported from `@prisma/adapter-pg`. `class PrismaService extends PrismaClient` therefore needs a constructor that calls `super({ adapter: new PrismaPg({ connectionString }), ... })`.
- The connection string comes from `ConfigService.getOrThrow<string>('DATABASE_URL')` (ConfigModule is `isGlobal: true` since 01-03, so no import is needed in PrismaModule). A constructor parameter property `private readonly config: ConfigService` cannot be used before `super()`; take it as a plain constructor parameter and use it only inside the `super(...)` call expression.
- Nest 12.1.3 `INestApplication.enableShutdownHooks(signals?, options?)` exists. Lifecycle order on shutdown: signal -> `onModuleDestroy` -> `beforeApplicationShutdown` -> `onApplicationShutdown`.
- Tagged-template raw SQL: ``this.prisma.$queryRaw`SELECT 1 AS ok` `` sends parameters as bind variables; `$queryRawUnsafe` / `$executeRawUnsafe` with string concatenation is forbidden for anything touching user input.
- Existing wiring to respect: `AppModule` imports ConfigModule, HealthModule, DemoModule and registers APP_FILTER; `main.ts` (02-03 version) ends with `app.listen`; `DemoModule` declares `DemoController` only.
</interfaces>
