<interfaces>
Verified in a scratch project on 2026-10-16 (Prisma 7.10.1, tsx 4.23.15):
- `migrations: { path: "prisma/migrations", seed: "tsx prisma/seed.ts" }` in `prisma.config.ts` makes `npx prisma db seed` print "Running seed command `tsx prisma/seed.ts` ..." and run it. In Prisma 7 the seed command is configured here, NOT under a `"prisma"` key in package.json. `migrate dev`/`migrate reset` no longer run the seed automatically; only `db seed` does.
- A standalone script cannot use Nest DI: build the client by hand: `new PrismaClient({ adapter: new PrismaPg({ connectionString: process.env.DATABASE_URL }) })`, imports `PrismaClient`, `Role` from `../src/generated/prisma/client`, `PrismaPg` from `@prisma/adapter-pg`, `import 'dotenv/config'` first (tsx does not load `.env`). Always `await prisma.$disconnect()` in a `finally` so the script exits.
- Idempotency pattern: `prisma.user.upsert({ where: { email }, update: {}, create: {...} })`. Empty `update` means an existing row is left untouched (password hash not rewritten); the `@unique` on `email` is the database-level backstop.
- Express uses `bcryptjs ^3.0.3` (see backend/package.json); this plan uses the same library at cost 10 (AUTH-07). Its version 3 ships its own types (no `@types/bcryptjs`). `hash(password, 10)` is async.
- Express password rule to respect in the seed: at least 6 characters (WEAK_PASSWORD). Express email regex: `^\w+([.-]?\w+)*@\w+([.-]?\w+)*(\.\w{2,3})+$`; the default seed emails `admin@example.com` and `user@example.com` satisfy it.
- Environment variables (read from `process.env` directly, deliberately NOT added to the Joi schema, because the seed is a dev tool and the running app must not require them): `SEED_ADMIN_EMAIL` (default `admin@example.com`), `SEED_ADMIN_PASSWORD` (required, no default), `SEED_NORMAL_EMAIL` (default `user@example.com`), `SEED_NORMAL_PASSWORD` (required, no default).
- npm 11 may print `install-scripts` warnings (esbuild, a dependency of tsx, has a postinstall); in the scratch test tsx worked without approving anything. Report any warning, do not approve blindly.
</interfaces>
