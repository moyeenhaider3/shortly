VERSION DECISION (verified on 2026-10-16 with `npm view`, do not guess):
- `npm view prisma dist-tags` -> `latest` is `8.0.0-rc.23`, a release candidate with a different workflow (no `schema.prisma`, no `generator`/`datasource` blocks, `contract emit` instead of `prisma generate`, no `@prisma/client`). `@prisma/client` and `@prisma/adapter-pg` `latest` are `7.10.1`. A bare `npm install prisma` would therefore install the wrong major.
- This project (roadmap Day 3, ROADMAP success criteria) uses `schema.prisma` + `prisma migrate dev` + `prisma db seed`, so ALL three packages are pinned to exactly `7.10.1`.
- Prisma 7 differences from the Day-3 roadmap doc (which shows the Prisma 5/6 style): (1) the connection URL is NOT in `schema.prisma` any more; it lives in `prisma.config.ts` (`datasource.url`); (2) the generator is `prisma-client` (not `prisma-client-js`) and `output` is REQUIRED, the client is generated as TypeScript source into your repo, not into node_modules; (3) the client needs a driver adapter (`@prisma/adapter-pg`) at construction (used from plan 03-02); (4) `prisma migrate dev` does NOT run `prisma generate` any more; (5) the CLI no longer reads `.env` itself, `prisma.config.ts` must `import "dotenv/config"`; (6) `npx prisma init` writes a file named `prisma7.config.ts` and appends a placeholder DATABASE_URL to `.env`, so do NOT use it, create the two files by hand.
- Engines: prisma 7.10.1 needs Node ^20.19 || ^22.12 || >=24; `.nvmrc` is 24 and the dev machine runs 26: fine.

- What an ORM schema file is; Prisma schema language (models, enums, scalar types, `?` optional, attributes `@id @unique @default @updatedAt @db.Uuid`, block attributes `@@index`), relations (scalar FK field + relation field + `onDelete`).
- Relational modelling vs the embedded Mongoose document: why Visit became a table.
- Unique constraint vs index; nullable unique; why `@unique` already implies an index.
- Prisma 7 layout: `prisma.config.ts`, generator `prisma-client` with a required `output`, generated client is source code in the repo and is git-ignored, `prisma generate` is a separate step.
- Migrations: `migrate dev` (diff schema vs DB, write SQL, apply, record in `_prisma_migrations`), why `migrations/` is committed, shadow database, reading `migration.sql`.
