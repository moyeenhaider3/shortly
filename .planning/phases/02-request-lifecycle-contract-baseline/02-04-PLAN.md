<interfaces>
Behaviour to assert (from backend/src/app.ts and error.middleware.ts):
- `GET /health` -> 200 `{ success: true, message: 'Server is healthy and running', timestamp: <ISO string> }`.
- Unknown route -> 404 `{ success: false, message: 'Cannot find <METHOD> <originalUrl> on this server', code: 'NOT_FOUND' }`. Use only paths Express's `GET /:shortCode` redirect route cannot match: `GET /api/nope`, `GET /api/nope?x=1`, `GET /nope/deeper`, `POST /nope`, `DELETE /api/nope`. A plain `GET /nope` is `URL_NOT_FOUND` on Express (redirect router) and is covered in 02-05.
- Malformed JSON body (`Content-Type: application/json`, body `{bad`) on any POST -> 400 `{ success:false, message:<string>, code:'entity.parse.failed' }`. The message text comes from the JS engine and is not asserted exactly.
- Envelope: every error body has exactly the keys success, message, code.

Test-project conventions: Jest (CJS) with ts-jest, supertest, TypeScript strict, tests run serially (later specs share state). Jest default timeout raised to 15000 ms (Render cold starts are not a concern locally, but Mongo can be slow on first call).
</interfaces>
</context>

<concepts>
- Contract testing: assert only what crosses the wire (status, headers, JSON), so the same suite validates two different implementations.
- supertest against a URL string (no in-process app, unlike `Test.createTestingModule` e2e tests in Phase 7).
- Test isolation by unique data (used heavily in 02-05) and serial execution.
- Fail-fast configuration (same principle as the Joi config in 01-03).
</concepts>
