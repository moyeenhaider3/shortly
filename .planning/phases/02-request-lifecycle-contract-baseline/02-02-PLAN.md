<interfaces>
Express behaviour to reproduce:
- `notFoundHandler`: message `Cannot find ${req.method} ${req.originalUrl} on this server`, status 404, code `NOT_FOUND`.
- `errorHandler` client-safe rule for body-parser errors: `err.expose === true && typeof err.type === 'string'` gives status `err.statusCode || err.status`, code `err.type` (e.g. `entity.parse.failed`, `entity.too.large`), message `err.message`.
- `requestLogger`: `console.log(`[${new Date().toISOString()}] ${req.method} ${req.originalUrl}`)`.
- `app.set('trust proxy', 1)`; `cors({ origin: "*", credentials: true, methods: ['GET','POST','PATCH','DELETE','OPTIONS'], allowedHeaders: ['Content-Type','Authorization'] })`.

IMPORTANT parity caveat (found in backend/src/app.ts): Express mounts `redirectRouter` (`GET /:shortCode`) before the 404 handler. So on Express a single-segment GET such as `/nope` returns 404 `URL_NOT_FOUND` ("Short URL not found or has been deactivated"), NOT `NOT_FOUND`. Nest has no redirect controller until Phase 5, so `/nope` returns `NOT_FOUND` on Nest for now. All 404 comparisons in this phase therefore use a path Express's redirect route cannot match: `/api/nope`, `/nope/deeper`, or a non-GET method such as `POST /nope`.
</interfaces>
</context>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser/client -> API | Untrusted bodies (malformed JSON), untrusted headers (`Origin`, `X-Forwarded-*`) |
| API -> console logs | Request URLs are written to logs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05 | I | Filter's body-parser branch | mitigate | Only errors with `expose === true` and a string `type` are reported as-is; everything else (including any 5xx) maps to the generic 500 body, mirroring Express's isClientSafe rule |
| T-02-06 | D | Malformed or oversized JSON | mitigate | Body parser rejects early with 400/413 envelope; no handler runs; parse error never reaches a 500 |
| T-02-07 | S | `trust proxy` = 1 trusting spoofable `X-Forwarded-*` | accept | Same as Express (documented in backend README); matches deployment behind Render's single proxy; revisit in Phase 6 hardening |
| T-02-08 | I | CORS `origin: *` with credentials | accept | Parity decision (Flutter uses Bearer header, browsers ignore wildcard+credentials); explicit allow-list is a Phase 6 candidate |
| T-02-09 | T | Log injection via crafted URL in the request log | mitigate | `originalUrl` from Node is percent-encoded for control characters; the line is a single `Logger.log` string, no format-string interpolation of user input |
</threat_model>
