Exact Express behaviour to assert (status / code / message), from the source files above.

Auth (`/api/auth`):
- signup 201, message `User registered successfully`, `data.user` = {id,name,email,role}, `data.token`; `Set-Cookie: token=...; HttpOnly; SameSite=Lax`; role always NORMAL even if `role:"ADMIN"` sent; email returned lowercased.
- signup/createUser errors in order: 400 VALIDATION_ERROR `Name, email, and password are required`; 400 VALIDATION_ERROR `Name must be between 2 and 50 characters`; 400 VALIDATION_ERROR `Please provide a valid email address`; 400 WEAK_PASSWORD `Password must be at least 6 characters long`; 409 EMAIL_ALREADY_EXISTS `Email is already registered`. Valid emails must match `^\w+([.-]?\w+)*@\w+([.-]?\w+)*(\.\w{2,3})+$` (use `name_<suffix>@example.com`; a 4-letter TLD such as `.test` is rejected).
- login 200, message `Logged in successfully`, cookie + `{user,token}`; email is case-insensitive; wrong password and unknown email both 401 INVALID_CREDENTIALS `Invalid email or password`; missing email or password 400 VALIDATION_ERROR `Email and password are required`.
- logout (auth required) 200 `Logged out successfully`, `Set-Cookie` clears `token`.
- me (auth required) 200 `{success,data}` where `data` is the user without `passwordHash`; Express returns Mongo `_id`, so specs read the id as `data.id ?? data._id`.
- auth middleware: cookie first, then `Authorization: Bearer`; none -> 401 UNAUTHORIZED `You are not logged in. Please log in to gain access.`; bad/expired token -> 401 INVALID_TOKEN `Invalid or expired authentication token`; valid signature but user gone -> 401 USER_DELETED `The user belonging to this token no longer exists`. JWT is HS256 with payload `{ userId }` signed with the target's secret.
- role middleware: 403 FORBIDDEN `You do not have permission to perform this action`.

URLs (`/api/urls`; everything except `check/:alias` needs auth):
- `GET /check/:alias` (public) 200 `data` = `{alias, available:true}` or `{alias, available:false, reason}`; reasons: `Alias must be between 3 and 30 characters and contain only letters, numbers, or hyphens`; `'<alias>' is a reserved system keyword and cannot be used`; `Custom alias is already in use`. Alias is trimmed and lowercased. Reserved: api, admin, auth, dashboard, login, logout, signup, health, public, static, assets, favicon.ico, robots.txt, sitemap.xml, urls, users.
- `POST /` 201 `data` = {id, originalUrl, shortCode, customAlias, shortUrl, clickCount:0, isActive:true, createdBy, createdAt, updatedAt}; random code matches `^[A-Za-z0-9]{7}$`; `shortUrl` = `<protocol>://<host>/<shortCode>`; custom alias is lowercased and becomes the shortCode. Errors: 400 ORIGINAL_URL_REQUIRED `Original URL is required`; 400 INVALID_URL_FORMAT `Invalid URL format. URL must start with http:// or https://` (ftp:// and plain text); 400 INVALID_ALIAS with the check reason text.
- `GET /` 200 `{success, count, data:[...]}` newest first, active only. Express quirk: an ADMIN sees only their own links. Nest deliberately lists everyone's active links for ADMIN (documented decision; asserted via env `ADMIN_SEES_ALL`).
- `GET /:id`: 400 INVALID_ID `Invalid URL ID format`; 404 URL_NOT_FOUND `URL not found` (missing or inactive); 403 FORBIDDEN `You do not have permission to access this resource` (not owner and not ADMIN); ADMIN may read any.
- `PATCH /:id` body `{originalUrl}` 200 `URL updated successfully`; invalid -> 400 INVALID_URL_FORMAT `Valid original URL is required` (checked before the id).
- `DELETE /:id` 200 `URL deactivated successfully`; afterwards GET by id is 404, it is gone from the list and from redirects; deleting again is 404 URL_NOT_FOUND.
- `GET /:id/analytics`: 200 `data` = {id, originalUrl, shortCode, customAlias, totalClicks, lastVisitedAt (null if none), createdAt, recentVisits:[{visitedAt, ip, userAgent}] newest first, max 10}; 400 INVALID_ID; 404 URL_NOT_FOUND; 403 FORBIDDEN `You do not have permission to view analytics for this URL`.

Redirect: `GET /:code` -> 302 with `Location` = original URL, visit recorded with ip = raw `x-forwarded-for` header when present, user agent from the request. Unknown/inactive -> 404 URL_NOT_FOUND `Short URL not found or has been deactivated`.

Users (`/api/users`, ADMIN only): `GET /` 200 `data` = [{id,name,email,role,createdAt}] newest first, no passwordHash; `POST /` body {name,email,password,role} 201 `User created successfully`, `data` the public user, NO `Set-Cookie`; errors as createUser (above) plus 400 INVALID_ROLE `Role must be one of: ADMIN, NORMAL` (also when role is missing). NORMAL token -> 403 FORBIDDEN; no token -> 401 UNAUTHORIZED.

Env vars (read lazily via `requireEnv`): `ADMIN_EMAIL`, `ADMIN_PASSWORD` (a pre-existing ADMIN in the target), `TARGET_JWT_SECRET` (the target's JWT secret; Express default is in backend/.env or its fallback), `GHOST_ID` (a well-formed id that matches nothing; default `000000000000000000000000`; Nest uses `00000000-0000-4000-8000-000000000000`), `ADMIN_SEES_ALL` (`true` for Nest, unset/`false` for Express).
